## 3. 没用上的模块

本题未使用 `core.ode`、`core.fitting`、`core.sensitivity`、`core.spatial`、`core.units`、`core.performance`。

- 本题没有常微分方程、数据拟合或随机/统计标定，不应强行调用前三者。
- 输入在题目专用常量处一次性由 cm 写成 m，内部全程 SI/rad，没有必要为固定常量强行调用 `core.units`。
- 223 块板凳规模下，NumPy AABB 广播粗筛已经足够；没有为“看起来用了空间模块”而改成 KDTree。
- 性能计时采用题目脚本内的 `perf_counter`，未为少量计时强行套 `core.performance`。

## 4. 实战发现的 core 缺陷

### C 类：core 通用能力确实存在缺陷

**未发现。** 全项目 50 项回归测试通过；本次没有修改 `core/`。

### B 类：当前 core API 不方便

| 问题 | 影响 | 本次处理 | 测试 |

### A 类：题目专用问题

- 223 节链式最近根、板凳尺寸/孔距、允许相邻板凳共享把手、排除非相邻板凳碰撞、S 形调头曲线和官方模板行列语义均为 2024A 业务规则。
- 有向矩形 SAT 本身可抽象，但尚无第二道题验证 API 形态，因此保留在 `common.py`，避免一次实战就污染 core。

## 5. 实战发现的 AGENTS.md 缺陷

发现并修复两项 D 类规则问题：

1. 原规则固定 `problems/qX/`、`results/qX/`，在历年题库中会让不同年份的 Q1 相互覆盖。现补充 `problems/<year><letter>/q1.py` 与 `results/<year><letter>/` 的题目标识命名。
2. 原性能顺序把 NumPy 放在消除重复计算之前，与本题要求和实际瓶颈不一致。现统一为“减少重复计算 → 预计算/缓存 → NumPy → 空间筛选 → Numba → 并行”。

原有“一张大图最多两个子图”规则有效地发现了 Q4 初版四子图问题；现已拆成两张双子图，旧三格式图已删除并由新图替代。

同时补充 `knowledge/07_collision_and_occlusion.md`：临界设计参数必须基于完整过程的 `G(p)=min_t c(p,t)`，不能用终点间隙替代。`knowledge/14_performance.md` 同步修正优化顺序。

## 6. 数值精度

### 6.1 求根与事件

| 检查 | 结果 |
|---|---:|
| Q1 弧长反解最大残差 | 2.140×10⁻¹⁰ m |
| Q2 首次碰撞事件间隙残差 | 2.137×10⁻¹⁵ m |
| Q2 1/0.5/0.25 s 粗步长经精化后的时刻最大差 | 2.274×10⁻¹³ s |
| Q2 在 `t*−10⁻⁴ s` 的间隙 | +2.632×10⁻⁶ m |
| Q2 在 `t*+10⁻⁴ s` 的间隙 | −2.632×10⁻⁶ m |
| Q3 临界间隙残差 | 1.335×10⁻¹⁴ m |
| Q3 螺距减/增 10⁻⁵ m 后的最小间隙 | −9.981×10⁻⁶ / +9.981×10⁻⁶ m |
| Q5 龙尾离开调头曲线的求根残差 | 5.080×10⁻¹³ m |
| Q5 极限速度回代残差 | 1.776×10⁻¹⁵ m/s |

Q3 暴露了一个重要模型陷阱：只检查龙头到达 4.5 m 边界会得到偏小螺距。真实临界接触发生在龙头半径 4.572603 m 处，因此使用完整进入过程的最小间隙。

### 6.2 223 条距离约束与误差沿龙身传播

| 状态 | maximum (m) | mean (m) | P95 (m) |
|---|---:|---:|---:|
| Q1 全部 301 个时刻 | 1.344×10⁻¹⁰ | 1.115×10⁻¹⁰ | 1.171×10⁻¹⁰ |
| Q2 临界时刻 | 1.104×10⁻¹⁰ | 7.726×10⁻¹¹ | 1.097×10⁻¹⁰ |
| Q3 临界状态 | 1.093×10⁻¹⁰ | 9.799×10⁻¹¹ | 1.087×10⁻¹⁰ |
| Q4 全部 201 个时刻 | 1.687×10⁻¹¹ | 1.394×10⁻¹² | 8.263×10⁻¹² |
| Q5 限制状态 | 1.438×10⁻¹¹ | 1.470×10⁻¹² | 8.522×10⁻¹² |

每一条链的误差已导出到 `chain_error_by_link.xlsx`。Q1–Q3 的平均单链误差与节点编号正相关，Q2 首/末 10% 链段均值约为 1.08×10⁻¹¹ 与 1.10×10⁻¹⁰ m；原因是螺线外侧的角参数更大，`brentq` 的相对角度容差映射成稍大的空间误差。误差始终在 10⁻¹⁰ m 量级，未出现随 223 次递推失控的数量级增长，对 10⁻⁶ m Excel 输出没有影响。复合路径使用弧长坐标求根，Q4/Q5 不呈尾部增长。

### 6.3 速度与网格收敛

- Q1 以 `h=10⁻³ s` 中心差分验证解析速度传播，最大误差 6.721×10⁻⁹ m/s。
- Q4 光滑段中心差分最大误差 3.286×10⁻⁷ m/s；三个曲率跳变连接点的 `h/h/2/h/4` 误差比为 1.99967、1.99983，符合 C¹ 路径上一阶跨界差分收敛。
- Q5 错位局部网格由 0.1 m 加密到 0.0125 m，采样峰与连续优化峰的差由 5.770×10⁻³ 降至 9.462×10⁻⁵；连续优化后再做速度上、下 10⁻⁶ m/s 扰动，约束方向正确。

### 6.4 碰撞几何人工测试

板凳按有长宽的有向矩形判定，不使用中心点替代。测试覆盖明显分离、刚好接触、明显相交、近似平行以及 ±10⁻⁹ m 浮点边界；所有测试通过。碰撞对先用 AABB 广播粗筛，再用 SAT 精判，真正相交的矩形不可能被粗筛漏掉。

## 7. 性能

| 阶段 | 耗时/规模 | 主要瓶颈 |
|---|---:|---|
| Q1 正式计算 | 3.635 s，301 个状态 | 每节弦长求根；单状态平均 0.01186 s |
| Q2 全流程 | 29.113 s | 0–300 s 的 1 s 排除扫描与三档事件扫描 |
| 单次纯碰撞检测 | 平均 0.02161 s | 223 矩形构造、AABB 候选与 SAT |
| 单次螺线整龙构造 | 平均 0.01192 s | 223 次最近弦长根 |
| Q3 全流程 | 65.613 s，1870 个唯一状态 | “螺距外层根 + 龙头角度内层极小化”的嵌套计算 |
| Q4 正式 201 时刻 | 14.925 s | 复合路径中每个把手的最近弧长根；单状态平均 0.07408 s |
| Q4 碰撞审计 | 8.220 s | 重点区 0.5 s、外部 5 s 的几何抽检 |
| Q5 全流程 | 69.429 s | 385 点全程粗扫描 28.018 s；12 个候选精化 10.562 s；其余为收敛/导出 |

复杂度主要为 `O(N_handles × root_iterations)` 的链式状态构造，碰撞部分在粗筛后为 `O(C_candidates)`。本题先消除重复状态、缓存 Q2/Q3/Q5 目标值，再做 NumPy AABB 粗筛；在分钟级总耗时已经适合比赛，因此没有提前使用 Numba 或并行。独立 Excel 审查最初发现 `read_only.cell()` 重复扫描 XML，已改为 `iter_rows` 流式读取，审查时间从不可接受降到约 10 s。

## 10. 当前 A_MODELING 是否能够用于正式比赛

**PASS**

依据：五问均能在题目目录内实现，没有把板凳龙业务逻辑塞入 core；六个重点 core 模块均在适合的位置自然调用；公式、单位、最近根、物理矩形碰撞、连续事件、优化方向、链长、速度、模板和图片经过自动测试与独立反向审查；50 项项目测试全部通过；总运行时间为分钟级，适合三天正式比赛。

保留意见不影响 PASS：双 sheet 官方模板 API 尚不顺手，当前用题目局部包装解决；Q3/Q5 嵌套计算仍是主要性能瓶颈。二者都不阻塞比赛交付，也没有证据支持现在扩充 core。

## 11. 下一道历年 A 题最应该测试什么能力

下一题建议固定为 **2022 年高教社杯 A 题《波浪能最大输出功率设计》**，重点不是再测几何，而是验证本题完全没有覆盖的：
