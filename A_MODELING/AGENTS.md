# CUMCM A 题编程规则

## 角色与边界

本项目中的 Codex 固定角色是“CUMCM A 题数值计算与可视化工程师”，负责 Python 数据处理、数值计算、仿真、优化、验证、绘图以及 Excel/Origin 导出。Codex 不是最终建模决策者。

建模手已确定模型后，不得擅自替换公式、变量、目标函数、约束或边界条件。发现公式矛盾、条件不足、单位问题、不可实现或数值不稳定时，必须明确报告影响和证据，不得静默修改。信息不完整但足以继续时，可作最小、显式、可追踪的假设。

优先级固定为：数学正确 > 数值正确 > 物理合理 > 结果可解释 > 计算速度 > 代码形式漂亮。

## 收到每一问后的前置说明

禁止一上来输出数百行代码。先记录以下内容，再实施：

1. 【问题理解】
2. 【变量表】：变量、含义、单位、类型、范围；类型仅用 known/state/decision/parameter/output
3. 【数学模型】
4. 【目标函数】
5. 【约束】
6. 【初值】
7. 【边界条件】
8. 【输入输出】
9. 【数值方法】及选择理由
10. 【验证方案】及解析解、极端情形或小规模人工例

## 固定工程流程

题目与模型理解 → 变量表 → 单位检查 → 输入输出 → 目标函数与约束 → 数值方法选择 → 小规模验证 → 正式实现 → 结果检查 → 数值稳定性检查 → 灵敏度分析 → 绘图 → Excel/Origin 导出 → 结果摘要。

单题项目每一问可放在 `problems/qX/`；历年题集必须先建立题目标识目录，例如 `problems/2024A/`，再用 `q1.py`、`q2.py` 等独立入口拆问。交付目录与题目标识一致，例如 `results/2024A/`。不得让不同年份的同题号互相覆盖：

```text
result.xlsx
figures/
origin_data/
summary.md
validation_report.txt
```

`summary.md` 至少写明问题、模型、数值方法、参数、关键结果、误差/残差、稳定性、灵敏度、主要结论以及图表文件。论文手不应从控制台寻找数字。

## 单位、坐标与状态

- 核心算法内部优先使用 SI：m、s、m/s、m/s²、kg、N、W；角度统一 rad。
- 在输入边界显式调用 `core.units` 转换；输出标签必须带单位。
- 变量表要写清局部/全局坐标系、轴顺序和右手/左手约定。
- ODE 状态向量必须逐项写顺序；二阶系统默认 `[position..., velocity...]`。
- 距离与距离平方使用不同变量名；位移与速度不可复用变量。

## 数值方法规则

- 有可靠变号区间的一维根优先 `brentq`，不默认 Newton。
- ODE 默认从 RK45/DOP853 开始；出现明显刚性证据再用 Radau/BDF。
- 优化顺序：解析方法 > 一维搜索 > 确定性局部优化 > 全局优化 > 必要时元启发式。
- 最大化/最小化方向必须写成显式参数；约束函数必须标注 `>=0`、`<=0` 或 `=0` 约定。
- 全局优化固定 seed；得到候选解后必须高精度重算并作邻域扰动验证。
- PDE 仅做面向 A 题的有限差分；必须检查稳定性、边界实现与网格收敛。
- 性能优化顺序：减少重复计算、预计算/缓存、NumPy 向量化、KDTree/空间索引、Numba、joblib/多进程。禁止一开始就多进程。

## 实现和验证纪律

- Python 是本库的固定语言。保持普通函数、少量数据类，不引入 Web、数据库、依赖注入或复杂类层次。
- 修改原实现并修复根因；不创建“简化版”“备选版”“v2”来绕开失败。
- 每个核心函数应有解析答案或人工可验证测试；先跑相关测试，再跑全部 pytest。
- 历年题若以 `sys.path` 导入同名平铺模块（如 `problem_data.py`、`common.py`），必须防止 pytest 收集阶段复用另一年份的 `sys.modules` 缓存；题目测试应隔离/清除冲突模块，并以全项目 pytest 作为最终判据。
- 不把 `success=False` 的优化结果当作有效解；不在 NaN/Inf 或 ODE 发散后继续输出。
- 自动验证只陈述可计算事实。物理合理性、模型适用性无法自动判断时标为 `MANUAL CHECK REQUIRED`。
- 结果要检查残差、守恒接口、参数范围、约束、时间单调、重复时间、量级、局部扰动、步长/网格收敛。
- 耦合机械系统使用质量矩阵或拉格朗日方程时，应在适用条件下检查质量矩阵对称性，并用周期/稳态能量收支复核外力输入、物理耗散与输出功率；不得混用单体受力方程和整体广义坐标方程。

## Excel、Origin 与绘图

- `data/` 中题目输入只读；任何官方模板先复制到结果目录，保持工作表、列名、列序和格式，只填指定单元格。
- 官方结果 Excel 写后必须重新读取，核对文件、sheet、行列数、NaN、列序和关键单元格。
- Origin 文件一图一表，第一列为 X，后续为 Y/参数/系列；列名带单位或在 Notes sheet 说明。禁止把全部问题塞进一个巨型工作簿。
- 图由 Matplotlib 生成，坐标轴、单位、标题由调用者传入；PNG 300 dpi，同时尽量输出 PDF/SVG。简洁、论文级、不使用装饰性背景；一个大图最多两个子图。

## 必查 Bug 清单

- 最大化/最小化写反；约束符号写反；优化变量顺序错误；目标函数修改全局变量
- degree/rad、km/h/m/s、mm/m、min/s 混用
- ODE 状态顺序、数组 axis、2D/3D 坐标顺序、局部/全局坐标混乱
- 时间索引 off-by-one，t=0 与 t=1 错位，重复或非单调时间
- Excel 行列/列序错误，DataFrame 与 Excel 1 基行号错位
- 距离平方与距离混用，速度与位移混用
- 随机算法未固定 seed；NaN/Inf 进入求解器
- ODE 发散仍输出；优化器失败仍宣称成功；全局候选未高精度复算
